# v0.10.0 Benchmark 报告 —— 工具链该有多快

生成时间：见 `results.json`（`--iterations=200`）。

## 结果

| 步骤 | 耗时 | 吞吐 |
| --- | --- | --- |
| 解析契约 | 0.34 ms | 2,953 ops/sec |
| 生成 OpenAPI | 0.06 ms | 17,449 ops/sec |
| 序列化成 JSON | 0.10 ms | 10,356 ops/sec |
| doctor 环境自检 | 0.38 ms | 2,630 ops/sec |
| **全链路（解析 + 生成 + 序列化）** | **0.50 ms** | — |

## 怎么读

**0.5ms 是关键数字**。它的意义是：这个工具快到可以挂在**文件保存钩子**上，
每次保存都重新生成一遍文档，用户完全无感。

一旦慢到"需要手动跑一下"，文档就开始漂移——
而**漂移的文档比没有文档更糟**，因为它会误导人。

另外两点：

1. **解析（0.34ms）比生成（0.06ms）贵 5 倍** ——
   所以优化工具链该先动解析器，而不是生成模板
2. **doctor 0.38ms** —— 便宜到可以放进 pre-commit 与 CI，
   每次提交都跑，把"环境不对"拦在最早的地方

## 复现

```bash
pnpm bench v0.10.0 --iterations=200 --report
```

## 已知限制

- 只测了单文件契约；大契约（数百路由）的解析是线性增长，未测
- 未测 `dev` 的重启耗时：它取决于应用自身的启动时间，与框架无关
