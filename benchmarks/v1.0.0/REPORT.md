# v1.0.0 Benchmark 报告 —— 安全原语的成本

生成时间：见 `results.json`（`--iterations=2000`，密码哈希只跑 30 次）。

## 结果

| 操作 | 单次开销 | 吞吐 |
| --- | --- | --- |
| JWT 签发 | 0.02 ms | 54,666 ops/sec |
| JWT 验签 | 0.02 ms | 56,105 ops/sec |
| scrypt 哈希（N=2048） | 45.78 ms | 21.8 ops/sec |
| scrypt 校验 | 45.32 ms | 22.1 ops/sec |

## 这两个数字看起来矛盾，其实都对

**验签 0.02ms**：它是每条请求的固定成本，必须快。
0.02ms 相当于一条 HTTP 链路（约 500µs）的 4%，可以接受。

**哈希 45.78ms**：它**应该**慢。
通用哈希（MD5 / SHA-256）快到能在 GPU 上每秒跑几十亿次，
用来存密码等于没存。KDF 的全部价值就在于"故意慢"：
45ms 意味着离线爆破一个 8 位密码需要几十年的量级。

所以这里唯一需要注意的操作问题是：
**登录接口会占住一个线程 45ms**。

- 不要在高并发路径上同步哈希（用队列或限流保护登录接口）
- N=2048 是当前折中；CPU 变便宜后应当调高（哈希格式里记了 N，老密码照样能验）

## 复现

```bash
pnpm bench v1.0.0 --iterations=2000 --report
```

## 已知限制

- 只测了 HS256；RS256 / EdDSA 的开销显著更高（非对称运算）
- 未做与 bcrypt / argon2 的横向对比（选 scrypt 是因为 node 内置、零依赖）
