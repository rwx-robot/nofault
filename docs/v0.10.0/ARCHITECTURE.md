# v0.10.0 架构：工程化工具链

## 一句话

**文档由契约生成，而不是手写**——手写必然漂移，而漂移的文档比没有文档更糟。

这一版补的是"写代码之外、上线之前"的那一圈工具：
OpenAPI 生成、开发热重载、环境自检。

## 一、OpenAPI：同一份契约的第二种投影

契约已经写了一遍，用它同时产出：

- 服务端代码（v0.4.0 起）
- 客户端 SDK（未做，但有了 OpenAPI 就是顺手的事）
- **API 文档**

三者同源，才可能保证"文档说的就是代码做的"。

几个必须转对的地方：

| 契约 | OpenAPI | 错了会怎样 |
| --- | --- | --- |
| `/users/:id` | `/users/{id}` | 工具解析不了路径参数 |
| `@Path` 字段 | `in: path` + `required: true` | 参数跑到 query 里 |
| `@Query` 字段 | `in: query` | 参数跑到 body 里 |
| 无必填字段 | **省略** `required` 键 | 空数组在部分工具里被当成"全部必填" |

最后一条最反直觉，也最容易漏：
`required: []` 不是一个无害的空值，它的语义是"全部必填"的反面教材。

## 二、dev：热重载的三条纪律

1. **防抖** —— 编辑器保存常常一次触发多个事件。不防抖就重启三四次
2. **必须等旧进程真的退出** —— 不等的话新旧进程抢同一个端口，
   表现为"改了代码却没生效"，极难排查
3. **重启期间的变更不能丢** —— 记一笔，这轮结束后立刻再重启一次
