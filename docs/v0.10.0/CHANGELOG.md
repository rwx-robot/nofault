# Changelog — v0.10.0（2025 · 工程化工具链）

> 文档由契约生成，而不是手写 —— 手写必然漂移，而漂移的文档比没有文档更糟。

## 新增能力

### `nofaultctl openapi`
- 由同一份契约产出 OpenAPI 3.0 文档（纯函数 `openApiDocument()`）
- `:id` → `{id}`；`@Path` → `in: path`；`@Query` → `in: query`
- 无必填字段时**省略** `required` 键（空数组语义相反）
- 无响应类型用 204；所有操作都带上 422

### `nofaultctl dev`
- 监听目录变化自动重启，默认防抖 150ms
- 重启前**等旧进程真的退出**（否则抢端口，表现为"改了没生效"）
- 重启期间的变更不丢（记一笔，结束后立刻再重启）
- 进程自己崩溃**不自动重启**（避免在坏代码上反复启动刷屏）

### `nofaultctl doctor`
- 检查 Node 版本、`package.json` 的 type、装饰器元数据、`reflect-metadata`、源码目录
- **解析 tsconfig 的 `extends` 链**（不解析会大面积误报）
- 每项都给出可执行的修复建议；有 fail 时退出码 1，可直接进 CI

## 关键设计决策

| 决策 | 理由 |
| --- | --- |
| 文档由契约生成 | 手写必然漂移，而漂移的文档比没有文档更糟 |
| 无必填时省略 `required` 键 | `required: []` 在部分工具里被当成"全部必填" |
| dev 必须等旧进程退出 | 不然新旧进程抢端口，表现为"改了代码没生效" |
| 崩溃不自动重启 | 否则在坏代码上反复启动，刷屏且看不出原因 |
| doctor 要解析 `extends` | 假阴性比漏检更糟，会让人不信这个工具 |
| 检查项名字必须稳定 | 名字是 API 的一部分，不能随状态变化 |

## 测试

- +8：OpenAPI 路径参数/query 拆分/required 语义/数组引用/204 与 422；
  doctor 的失败项、通过项、**extends 解析**、缺失依赖提示
- 全量全通过；`tsc --noEmit` 与 `eslint` 全清

## 性能

| 步骤 | 耗时 |
| --- | --- |
| 解析契约 | 0.34 ms |
| 生成 OpenAPI | 0.06 ms |
| 序列化 | 0.10 ms |
| **全链路** | **0.50 ms** |
| doctor | 0.38 ms |

0.5ms 的意义：工具快到可以挂在文件保存钩子上，每次保存都重新生成。

## 已知限制

- `dev` 不编译，只重启
- doctor 不检查运行时问题（端口占用、数据库连接）
- OpenAPI 未生成 securitySchemes 与 examples
